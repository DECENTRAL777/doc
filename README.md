# Кронверкский децентрал им. Yimirs

Закрытая сеть доверенных узлов. **Текущий приоритет — качественный собственный
P2P-оверлей**, а не одновременная реализация хранилища, C2 и панели. Документы —
актуализируемый архитектурный прототип: что ещё не проверено кодом и испытаниями,
не объявляется гарантией.

## Принятые решения для overlay MVP

| Область                 | Решение                                                                                                                     |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Транспорт               | Собственный протокол поверх UDP/IPv4; без QUIC и совместимости с libp2p                                                     |
| Криптография соединения | `Noise_XX_25519_ChaChaPoly_SHA256`; небольшая проверенная библиотека после проверки GraalVM Static Native Image             |
| Идентичность            | `NodeId` — доменно разделённый SHA-256 от публичного ключа узла Ed25519; отдельный X25519 — для Noise                       |
| Допуск                  | Один операторский Ed25519 issuer вне агентов подписывает сертификаты и список отзывов; узлы знают только его публичный ключ |
| Поиск                   | Несколько seed-адресов, затем ограниченная Kademlia по XOR: `PING` и `FIND_NODE` только между допущенными узлами            |
| Передача                | Версионированные бинарные UDP-кадры до 1200 байт, небольшие неупорядоченные сообщения, ACK/повторы/дедупликация             |
| Обход NAT               | Отдельный следующий этап: UDP hole punching и слепой relay конечной Noise-сессии                                            |
| Первый стенд            | Три узла в IPv4 LAN: третий находит второго через seed, все трое имеют проверенный допуск                                   |
| Сборка                  | JDK 25, Make/javac без Maven/Gradle, GraalVM Static Native Image как gate этапа исследований                                |

Noise защищает содержимое **между конечными узлами**, в том числе когда будущий relay
пересылает зашифрованные пакеты, не завершая их Noise-сессию. Отдельный ключ
шифрования хранимых сообщений сейчас не нужен: доставка сообщений отсутствующему
получателю не входит в overlay MVP.

## Границы

- Текущий `agent/` из `concept/` — учебный прототип прямого TCP-вызова команды. Его
  формат, счётчик и ключи не являются протоколом нового оверлея.
- Первый результат: Noise-соединение двух допущенных узлов и проверенный поиск/ping
  трёх узлов в LAN. NAT/relay выполняются следующим проверяемым этапом.
- Хранилище — надстройка над P2P-оверлеем, а **не** над C2. Взаимный порядок
  разработки C2, хранилища и обновлений после готового оверлея пока не зафиксирован.
- IPv6 **не** является транспортом первого MVP. Выводимый IPv6-адрес VPN — будущий
  sidecar, основанный на криптографической идентичности узла и использующий готовый
  оверлей; его протокол ещё не выбран.
- Политика работы при устаревшем состоянии отзывов во время разделения сети пока
  **не определена**. Не следует обещать ни fail-open, ни fail-closed до отдельного
  решения и испытания.

## Правила решений

Изменения wire format, идентичности и допусков сначала фиксируются в документах.
Каждая обещанная возможность получает явный приёмочный тест; граница, по которой
проверенная возможность превращается в стабильный протокол v1, описана в
[Маляве](МАЛЯВА.md). Непроверенные параметры отмечаются как открытые решения.
