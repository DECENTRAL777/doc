# Малява

Черновик **собственного бинарного wire format** для IPv4 UDP/Noise оверлея.
Здесь нет libp2p-протоколов, QUIC, CBOR, GossipSub и схем будущих C2/хранилища.
Статус v1: номера и подписываемые байты предлагаются для проверочных векторов;
заморозить их можно только после межреализационной проверки этапа 0.

## Правила

- Числа передаются в network byte order (big-endian). Списки имеют явную длину,
  строки в кадрах первого MVP не используются.
- UDP-датаграмма **целиком** не более 1200 байт; пакет большего размера
  отклоняется до разбора. Фрагментации IPv4 и транспортных сообщений в v1 нет.
- Неизвестная версия или тип отклоняются. Неизвестные обязательные поля не
  игнорируются; расширение требует новой версии.
- Размер каждого поля проверяется до выделения памяти. Точные полученные байты
  подписанного объекта сохраняются вместе с проверенной версией.
- Для каждого назначения подписи используется отдельный ASCII-префикс и `0x00`.
  Идентификаторы и ключи никогда не выводятся из текстового представления адреса.

## Идентификаторы

```text
network_id = 16 случайных байт на логическую сеть
NodeId     = SHA-256(ASCII("decentral777:node:v1") || 0x00 || ed25519_public_raw32)
```

`NodeId` имеет длину 32 байта. Отдельный Noise X25519 public key тоже 32 байта,
но не определяет NodeId. Это не libp2p PeerId и не E2E-ключ для офлайн-хранения.

## Внешний UDP-кадр v1 (черновик)

```text
magic[4] = ASCII("D777")
version:u8 = 1
type:u8
network_id[16]
session_id[8]
packet_no:u64
payload_len:u16
payload[payload_len]
```

Размер заголовка — 40 байт. `payload_len` должен точно совпадать с остатком
датаграммы; лишние байты запрещены. `session_id` генерируется случайно при новом
рукопожатии и не переиспользуется при переподключении. Типы в первом профиле:

| Тип           | Payload и условие                                                                                           |
| ------------- | ----------------------------------------------------------------------------------------------------------- |
| `1` `NOISE_1` | Первое сообщение Noise XX; до авторизации                                                                   |
| `2` `NOISE_2` | Второе сообщение Noise XX; до авторизации                                                                   |
| `3` `NOISE_3` | Третье сообщение Noise XX; до авторизации                                                                   |
| `4` `DATA`    | Зашифрованное Noise transport payload; требует авторизации, кроме `AUTH`                                    |
| `5` `ACK`     | Зашифрованное подтверждение номера принятого DATA-пакета; ACK для `AUTH` допустим до завершения авторизации |

Для `DATA`/`ACK` аутентифицированный внешний заголовок используется как AEAD
associated data транспортной Noise-сессии. `packet_no` уникален в направлении
отправки данного сеанса. Получатель отклоняет старые номера за пределами
ограниченного окна и не передаёт дубликат наверх. Для рукопожатия `packet_no`
соответствует шагу Noise, а повтор того же шага не создаёт новый сеанс. Таймаут
состояния handshake и число повторов ограничены. До подтверждённого handshake
нельзя использовать `PING` и DHT.

## Сертификат узла

На первом этапе одно делегирование и один операторский Ed25519 issuer без
цепочки сертификатов или ролей:

```text
schema_version:u8 = 1
network_id[16]
serial[16]                 // случайный номер
identity_ed25519[32]
noise_x25519[32]
not_before:u64             // Unix seconds, UTC
not_after:u64              // Unix seconds, UTC
issuer_signature[64]
```

Issuer подписывает `ASCII("decentral777:cert:v1") || 0x00 || поля от
schema_version до not_after включительно`. Корневой публичный ключ берётся
только из локального trust bundle. Сериал уникален для issuer, `not_after` больше
`not_before`. Размер сертификата — 177 байт.

`Noise_XX_25519_ChaChaPoly_SHA256` выполняется с `network_id` и версией в
контексте (prologue). После трёх Noise-сообщений **каждая сторона** в зашифрованном
`AUTH` отправляет сертификат и Ed25519-подпись:

```text
ASCII("decentral777:auth:v1") || 0x00 || network_id || role:u8 || noise_handshake_hash
```

`role` различает инициатора и ответчика (`1` и `2`); `noise_handshake_hash` —
итоговый hash полного рукопожатия из Noise API. Узел проверяет подпись, срок и
сеть сертификата, вычисляет NodeId из Ed25519 ключа, сравнивает Noise X25519 key
с фактическим статическим ключом пира и проверяет отзыв. Никакие overlay-команды
не обрабатываются, пока **обе** стороны не завершили эти проверки. Возможность
получить итоговый hash из выбранной Noise-библиотеки подтверждается на этапе 0.

## Защищённые сообщения первого MVP

Внутреннее сообщение имеет `kind:u8 || request_id:u64 || поля kind`. Типы:

| kind          | Поля                                                                         |
| ------------- | ---------------------------------------------------------------------------- |
| `AUTH`        | сертификат и подпись стенограммы; только при переходе в авторизованный сеанс |
| `PING`        | без дополнительных полей                                                     |
| `PONG`        | без дополнительных полей, повторяет request_id                               |
| `FIND_NODE`   | target_node_id[32]                                                           |
| `NODES`       | count:u8, затем до 8 записей `(node_id[32], ipv4[4], port:u16)`              |
| `REVOCATIONS` | подписанный оператором снимок отозванных serial                              |

`PING`, `FIND_NODE` и ответы — короткие самостоятельные сообщения, не части
упорядоченного потока. `request_id` сопоставляет ответ с запросом. `NODES`
возвращает **непроверенные адресные подсказки**; получатель связывает NodeId с
endpoint только после собственного успешного Noise/auth-рукопожатия.

Отправитель `DATA` ждёт шифрованный `ACK` с номером пакета. При потере ACK
повторяет то же сообщение ограниченное число раз; при повторе получатель
может ответить ACK вновь, но не выполняет запрос вторично. Таймаут, размеры
окон и лимиты памяти — конфигурация профиля, которую предстоит проверить
нагрузкой до freeze. Время истечения доставки ограничено: недоступный узел не
получит сообщение после завершения окна попыток.

## Подписанный список отзывов

Черновой формат ограниченного снимка:

```text
schema_version:u8 = 1 || network_id[16] || version:u64 || count:u8
|| serial[16] * count || issuer_signature[64]
```

Подпись покрывает `ASCII("decentral777:revocations:v1") || 0x00 || все поля,
кроме issuer_signature`. Список отсортирован по байтам serial, без дубликатов.
Версия монотонна и сохраняется на диске; более старый снимок отклоняется.
Первый кадр вмещает не более 64 serial (вместе с шифрованием и заголовком
датаграмма остаётся меньше 1200 байт). При превышении этого предела нужен
отдельный версионированный механизм страниц: обрезать список молча нельзя.

Подписанный снимок могут пересылать обычные допущенные пиры — получатель
проверяет подпись issuer, а не доверяет источнику доставки. Поведение при
длительном отсутствии свежего снимка **не определено** и не считается свойством
этого wire format.

## Проверка до заморозки v1

1. Бинарные векторы для кадра, NodeId, сертификата, AUTH и списка отзывов;
   побайтово одинаковая сериализация в двух независимых реализациях.
2. Отрицательные векторы: лишние байты, длина 1201, неподдержанная версия,
   другой `network_id`, испорченная подпись, неверный X25519 ключ и повтор.
3. Рукопожатие двух Native Image процессов на Alpine, затем поиск/ping трёх
   авторизованных узлов в IPv4 LAN.

Схемы C2, хранения, обновлений и IPv6 sidecar появятся отдельными версиями
только при реализации соответствующих надстроек.
